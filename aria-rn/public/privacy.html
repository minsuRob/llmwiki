2. Google 사용자 데이터 — 제한적 사용

llmwiki 가 Google API 로 받은 정보를 사용하고 다른 앱으로 전송하는 것은 Google API 서비스 사용자 데이터 정책의 제한적 사용(Limited Use) 요구 사항을 포함해 그 정책을 따릅니다.

  • Drive 데이터는 사용자가 보는 기능(업무 저장 · 받은 것 정리 · 자료 잇기)을 제공하는 데만 씁니다.
  • 판매하지 않고, 광고에 쓰지 않고, 신용도 판단 등 다른 목적에 쓰지 않습니다.
  • 범용 AI · 머신러닝 모델을 학습시키는 데 쓰지 않습니다.
  • 사람이 Drive 데이터를 읽는 일은 사용자의 명시적인 동의가 있거나, 보안 · 법적 의무 때문에 필요할 때만 있습니다.
  • 서버는 Drive 내용을 저장 · 색인하지 않습니다. 사용자가 요청한 읽기(예: 업무 목록 확인)는 그때 읽고 응답으로만 돌려줍니다.

3. AI 처리

  • 대화 기능: 사용자가 대화 화면에 쓴 글과 그 답을 만드는 데 필요한 맥락(할 일 · 일정 등)은 답을 만들기 위해 Anthropic 의 Claude API 로 보내질 수 있습니다.
  • AI 로 이어하기 · 정리 맡기기: 사용자가 직접 실행할 때만, 사용자가 고른 AI(Claude · Codex · Gemma)에 '맥락 묶음'을 넘깁니다. 묶음에는 사용자가 이어 둔 자료와 받은 것 조각의 발췌가 들어갈 수 있습니다. 묶음은 사용자 컴퓨터의 도구(Claude Code · Codex CLI)나 개발자가 운영하는 Gemma 서버에서 처리됩니다. Gemma 서버에 남는 묶음과 결과는 받은 뒤 지우는 것을 목표로 하며, 지금은 개발자가 직접 정리합니다. llmwiki 는 Drive 데이터를 자동으로 AI 에 보내지 않습니다.
  • MCP: 사용자가 자기 컴퓨터의 Claude Code 등에 llmwiki MCP 를 등록하면, 그 도구가 사용자 대화 중에 받은 것에 조각을 남기고 정리 제안을 낼 수 있습니다. 확정 · 삭제는 앱에서 사용자만 할 수 있습니다.
  • AI 가 낸 결과는 언제나 제안으로만 들어오고, 사용자가 받아들여야 반영됩니다.

4. 맡기는 곳(처리 위탁)

  • Anthropic(대화 기능의 Claude API)
  • 사용자가 직접 고른 AI 도구(Anthropic Claude Code · OpenAI Codex) — 사용자 자신의 계정과 컴퓨터에서 실행

5. 보관과 삭제

  • Drive 의 파일은 사용자 소유입니다. Drive 에서 언제든 지울 수 있고, llmwiki 를 그만 써도 그대로 남습니다.
  • Drive 연결 해제(설정 → Drive 연결 해제)를 누르면 Google 에서 열쇠를 거두고, 서버의 암호화된 열쇠와 MCP 열쇠를 모두 지웁니다. Google 계정의 서드파티 앱 권한에서 거둬도 다음 사용 때 서버 보관본을 지웁니다.
  • MCP 열쇠는 설정에서 언제든 거둘 수 있고, 거두면 바로 막힙니다.
  • 휴지통에 넣은 할 일 · 기록은 7일 뒤 비워집니다.
  • 계정과 서버 데이터 전체 삭제는 minsu.rob@gmail.com 으로 요청하면 30일 안에 처리하고 결과를 알려 드립니다.

6. 보안

  • 모든 통신은 HTTPS 로 합니다.
  • Drive 열쇠는 사용자별로 묶어 암호화하고, 앱(브라우저)은 서버 보관 자리를 읽을 수 없습니다.
  • 권한은 가장 좁게 씁니다(Drive 는 drive.file 하나).

7. 바뀌면

이 방침이 바뀌면 이 페이지의 시행일을 고치고, 중요한 변경은 앱 안에서 알립니다.

Privacy Policy (English)

Effective October 22, 2026 · Operated by llmwiki (an individual developer) · Contact minsu.rob@gmail.com

Summary. Your work items, notes and suggestions are stored as files you own in your Google Drive. The llmwiki server does not store Drive content; it only keeps an encrypted Drive connection key. Google user data is never sold, used for advertising, or used to train generalized AI models.

1. Information we receive and why

  • Google Sign-In (Firebase Authentication): account identifier, email, name and profile photo — to identify your account across devices.
  • Google Drive, drive.file scope only, after you choose "Connect Drive": to read and write work items, notes, sorting suggestions, raw AI results and summaries in the "llmwiki 작업실" folder the app creates, and to read the text of files you explicitly pick. The app cannot see any other file in your Drive.
  • Drive connection key (refresh token), connected email and timestamps — encrypted with AES-256-GCM and kept on the server only, so you are not asked again in new tabs. The app only receives 1-hour access tokens.
  • MCP keys you create in Settings — only a SHA-256 hash, a label and timestamps are stored. They let the llmwiki MCP on your own computer obtain 1-hour Drive access tokens.
  • Chat, tasks, calendar events, notes, concept graph and job notes — stored per user in Firebase Firestore to provide those features.
  • Operational logs (user id, action, counts, time) in Google Cloud Logging. Keys, tokens and file contents are never logged.

2. Google user data — Limited Use

llmwiki's use and transfer to any other app of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

  • Drive data is used only to provide user-facing features (saving work, sorting the inbox, linking sources).
  • It is not sold, not used for advertising, and not used for purposes such as determining creditworthiness.
  • It is not used to develop, improve or train generalized AI or machine-learning models.
  • Humans do not read Drive data unless you give explicit consent, or it is necessary for security purposes or to comply with applicable law.
  • The server does not store or index Drive content. Reads you request (for example, listing your work items) are returned in the response only.

3. AI processing

  • Chat: what you write in the chat screen, with the context needed to answer (tasks, events), may be sent to Anthropic's Claude API to generate replies.
  • Hand-off and inbox sorting: only when you start it, a context bundle is passed to the AI you choose (Claude, Codex or Gemma). The bundle may include excerpts from sources you linked and from inbox notes. It is processed by tools on your own computer (Claude Code, Codex CLI) or on a Gemma server run by the developer. Bundles and results left on the Gemma server are meant to be deleted after the result is received; for now the developer cleans them up manually. llmwiki never sends Drive data to an AI automatically.
  • MCP: if you register the llmwiki MCP in a tool on your computer, that tool can add notes to your inbox and submit sorting suggestions during your conversation. Only you can confirm or delete, in the app.
  • AI output always arrives as a suggestion and is applied only after you accept it.

4. Service providers

Google (Firebase Authentication, Firestore, Cloud Functions, Hosting, Cloud Logging, Google Drive API), Anthropic (Claude API for chat), and AI tools you choose to run with your own accounts (Anthropic Claude Code, OpenAI Codex).

5. Retention and deletion

  • Files in your Drive are yours. You can delete them at any time; they remain if you stop using llmwiki.
  • "Disconnect Drive" in Settings revokes the key with Google and deletes the encrypted key and all MCP keys from the server. Revoking access in your Google Account's third-party access page also causes the stored key to be deleted on next use.
  • MCP keys can be revoked in Settings at any time and stop working immediately.
  • Items in the trash are emptied after 7 days.
  • To delete your account and all server data, email minsu.rob@gmail.com; requests are completed within 30 days.

6. Security

All traffic uses HTTPS. Drive keys are encrypted and bound to your user id, and the app cannot read where they are stored. Access is kept to the narrowest scope (drive.file only).

7. Changes

If this policy changes, the effective date on this page is updated, and material changes are announced in the app.
