# 역할 분담 (검증으로 정한 것)

근거는 [results.md](results.md). 표본이 작아 바뀔 수 있다 — 바뀌면 이 표를 고친다.

| 일 | 담당 | 방식 |
|---|---|---|
| 위임 결과 검증(파싱·형식·내용) | **코드** `validateResult` | 동기. 통과해도 '제안' |
| 맥락 묶음 만들기 | **코드** `buildBundle` | 필수 블록은 안 자르고 자료만 예산에 맞춤 |
| 묶음 자료 고르기 · 검색 | **코드** BM25 | 동기 |
| 중복 공고 찾기 | **코드** 해시 · 단어 겹침 | 동기 |
| 마감일 명시 · AI 직무명 같은 표시 | **코드** 키워드 | 동기 |
| 자료 질의응답 · 요약 · 다음 행동 초안 · 추가 확인 표시 · 검토 순서 정렬 | **Gemma** | **비동기만**(분 단위), 진행 상태 표시 |
| 규칙이 약한 판단(경력 수준 등) | **Gemma** | 비동기. 코드가 확실한 건 코드가 먼저 |
| Laya 용 영어 질문 만들기 | **Gemma** | 질문 등록 때 1회, 저장해 재사용 |
| 조사 · 실제 작업 위임 | **Claude · Codex** | Electron 메인에서 CLI 비대화형 |
| 확정 | **사람** | 검토 카드 |

## Laya

- **지금 붙일 기능 없음.** 모든 구성에서 가장 강한 기준선(키워드)을 못 넘었다.
- 쓸 때는 반드시 **코드로 근거 줄만 자르고 + 영어 질문 + multilingual 고정**(긴 원문 · 한국어 질문이면 거의 항상 '예').
- 관찰 대상으로만 남긴다: 마감일 판단(근거 줄 방식 macro-F1 0.73).

## 운영

- 상주: Gemma(8K 컨텍스트) 1개 + Laya multilingual 1개까지. english 체크포인트는 같이 올리지 않는다.
- **동시 추론 금지** — 작업 큐 하나로 순차.
- Gemma 요청은 항상 `chat_template_kwargs.enable_thinking=false`(llama-server 가 기본으로 켠다).
- Gemma 생성 글은 화면에 보이기 전 주입 탐지 결과를 같이 표시하고, 상태·결정에 자동으로 쓰지 않는다.
